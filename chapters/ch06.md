# 챕터 6: 코드 실행과 테스트
> Bash 도구로 코드를 직접 실행하고 결과를 확인하기

## 학습 목표
- Bash 도구의 실행 범위와 제약을 이해한다
- 테스트 작성부터 실행까지 자동화하는 방법을 익힌다
- 주요 빌드 파이프라인과 Claude Code를 연동한다
- 에러 메시지를 효과적으로 디버깅하는 패턴을 학습한다

## 6.1 Bash 도구 이해: 명령어 실행의 범위와 제약

Claude Code의 Bash 도구는 실제 터미널 명령을 실행합니다. 이것은 강력하지만, 그만큼 이해하고 사용해야 합니다.

### Bash 도구가 할 수 있는 것

```
✅ 가능한 작업:
- 파일 시스템 탐색 (ls, find, tree)
- 코드 실행 (python app.py, node server.js)
- 패키지 설치 (npm install, pip install)
- 테스트 실행 (npm test, pytest, go test)
- 빌드 실행 (npm run build, make, gradle build)
- Git 명령 (git status, git diff, git log)
- 프로세스 관리 (ps, kill)
- 네트워크 요청 (curl, wget)
```

### 실행 환경 이해

```
Bash 도구 실행 환경:
┌────────────────────────────────────────────┐
│  현재 디렉토리: 세션 시작 위치             │
│  환경 변수: 사용자 쉘 환경 상속            │
│  타임아웃: 기본 120초 (설정 변경 가능)     │
│  권한: 현재 사용자 권한과 동일             │
└────────────────────────────────────────────┘

⚠️ 주의: 각 Bash 호출은 독립적인 쉘에서 실행됩니다.
cd 명령으로 디렉토리를 변경해도 다음 호출에 영향 없음.
→ 절대 경로 사용을 권장합니다.
```

### 승인이 필요한 명령

Claude Code는 다음 유형의 명령은 실행 전에 사용자 승인을 요청합니다:

```bash
# 데이터 삭제
rm -rf ./build/

# 시스템 수정
sudo apt install package

# 외부 서비스 접근
curl -X POST https://api.external.com/data

# 프로세스 종료
kill -9 1234
```

이는 의도하지 않은 영구적 변경을 방지하는 안전장치입니다.

> **💡 팁:** `--dangerously-skip-permissions` 플래그로 모든 명령을 자동 승인할 수 있지만, 프로덕션 환경에서는 절대 사용하지 마세요.

## 6.2 테스트 자동화: 단위 테스트 작성부터 실행까지

Claude Code와 함께하는 TDD(Test-Driven Development)는 개발 속도를 획기적으로 높입니다.

### TDD 워크플로우

```
Red → Green → Refactor 사이클을 Claude Code와 함께:

1. [Red] 실패하는 테스트 작성 요청
   "userService.createUser() 함수에 대한 테스트를 먼저 작성해줘.
    - 이메일 형식 검증
    - 중복 이메일 처리
    - 비밀번호 해싱 확인"

2. [Green] 테스트를 통과하는 최소 구현 요청
   "이 테스트들을 통과하는 createUser 함수를 구현해줘"

3. [Refactor] 코드 품질 개선
   "테스트가 통과하는 상태를 유지하면서 코드를 깔끔하게 리팩토링해줘"
```

### Jest 테스트 자동화

```bash
# 전체 테스트 실행
"npm test를 실행하고 실패한 테스트가 있으면 수정해줘"

# 특정 모듈 테스트
"auth 모듈의 테스트만 실행하고 커버리지를 보여줘"

# 워치 모드 (파일 변경 시 자동 재실행)
"npm run test:watch를 실행해줘"
```

실제 세션 예시:

```
사용자: "utils/validator.js의 테스트를 작성하고 실행해줘"

Claude Code의 행동:
1. validator.js 읽기 (Read 도구)
2. 테스트 파일 생성 (Write 도구)
   → utils/__tests__/validator.test.js
3. 테스트 실행 (Bash 도구)
   → npm test utils/__tests__/validator.test.js
4. 결과 분석 및 실패한 테스트 수정
```

### Python pytest 자동화

```bash
# 기본 테스트 실행
"pytest tests/ -v를 실행해줘"

# 커버리지 측정
"pytest --cov=src --cov-report=html tests/
 커버리지가 80% 미만인 파일을 찾아서 테스트를 추가해줘"

# 특정 마커
"@slow 마커가 붙은 테스트는 제외하고 실행해줘"
```

### 테스트 결과 분석 패턴

```bash
# 실패 원인 분석
"테스트를 실행했더니 다음 에러가 나왔어:
[에러 메시지 붙여넣기]
원인을 분석하고 수정해줘"

# 테스트 커버리지 개선
"현재 커버리지 리포트를 보여줘.
 커버되지 않은 중요한 코드 경로에 테스트를 추가해줘"
```

## 6.3 빌드 파이프라인 연동 (npm, make, pytest, gradle)

다양한 빌드 시스템과 Claude Code를 연동하는 방법을 알아봅니다.

### npm/yarn (Node.js)

```bash
# 의존성 설치 및 빌드
"npm install을 실행하고, 에러가 있으면 해결해줘.
 그 다음 npm run build를 실행해줘"

# 취약점 수정
"npm audit를 실행하고 moderate 이상 취약점을 수정해줘.
 단, 메이저 버전 업그레이드는 내가 확인 후 결정할게"

# 스크립트 자동화
"package.json에 다음 스크립트를 추가해줘:
 - lint:fix: ESLint 자동 수정
 - type-check: TypeScript 타입 검사만 (빌드 없이)
 - test:ci: CI 환경용 테스트 (커버리지 + JUnit 리포트)"
```

### Python (pip/poetry)

```bash
# 가상환경 설정
"Python 3.11 가상환경을 만들고 requirements.txt를
 설치해줘. 충돌하는 의존성이 있으면 해결 방법을 제안해줘"

# Poetry 사용
"poetry run pytest tests/ -v를 실행하고
 실패한 테스트를 수정해줘"
```

### Makefile 활용

```bash
# Makefile 생성
"이 프로젝트용 Makefile을 만들어줘:
 - make setup: 개발 환경 초기화
 - make test: 전체 테스트
 - make lint: 코드 스타일 검사
 - make build: 프로덕션 빌드
 - make deploy: 스테이징 배포
 - make clean: 빌드 산출물 정리"

# Makefile 실행
"make test를 실행해줘"
```

### Gradle (Java/Kotlin)

```bash
# 빌드 및 테스트
"./gradlew clean build를 실행하고
 테스트 리포트를 분석해줘"

# 특정 태스크
"./gradlew test --tests 'com.example.UserServiceTest'
 를 실행해줘"
```

### CI/CD 파이프라인 디버깅

```bash
# GitHub Actions 실패 분석
"GitHub Actions 빌드가 실패했어. 로그가 여기 있어:
[로그 내용]
실패 원인을 분석하고 .github/workflows/ci.yml을 수정해줘"
```

> **💡 팁:** CI 환경에서 Claude Code를 사용할 때는 `ANTHROPIC_API_KEY` 환경변수를 GitHub Secrets에 저장하고, `claude -p "명령어"` 형식으로 비대화형 모드를 사용하세요.

## 6.4 실행 오류 디버깅: 에러 메시지를 Claude Code에 전달하는 패턴

에러가 발생했을 때 Claude Code를 가장 효과적으로 활용하는 방법을 알아봅니다.

### 에러 전달의 황금 규칙

```
효과적인 에러 디버깅을 위한 정보:
┌────────────────────────────────────────────┐
│ 1. 완전한 에러 메시지 (truncate 하지 말 것) │
│ 2. 스택 트레이스 전체                      │
│ 3. 에러가 발생한 맥락 (어떤 작업 중?)      │
│ 4. 재현 방법                               │
│ 5. 예상했던 동작                           │
└────────────────────────────────────────────┘
```

### 실전 디버깅 세션

```bash
# 런타임 에러
"서버를 실행했더니 이런 에러가 나왔어:

Error: Cannot read properties of undefined (reading 'email')
    at UserController.getProfile (src/controllers/user.js:45:27)
    at Layer.handle [as handle_request] (node_modules/express/lib/router/layer.js:95:5)
    ...

GET /api/user/profile 요청을 보낼 때 발생해.
로그인한 상태인데 왜 이런 에러가 나는지 분석해줘"
```

```bash
# 빌드 에러
"TypeScript 컴파일이 실패했어:
src/types/api.ts:23:5 - error TS2322:
Type 'string | undefined' is not assignable to type 'string'.
   23     userId: userData.id,

어떻게 수정해야 해?"
```

```bash
# 테스트 실패
"이 테스트가 계속 실패해:
FAIL src/__tests__/auth.test.js
  ● AuthService › login › should return token on success
    Expected: 'valid_token'
    Received: undefined

    at Object.<anonymous> (src/__tests__/auth.test.js:34:28)

테스트 코드와 실제 구현을 같이 보고 왜 실패하는지 찾아줘"
```

### 재현 불가능한 에러 처리

```bash
# 간헐적 에러
"가끔 이런 에러가 나와. 재현이 안 되는데:
ConnectionError: Connection reset by peer

코드를 보고 이 에러가 발생할 수 있는 상황을 모두 찾아줘.
그리고 재현 가능한 테스트 케이스를 만들어줘"
```

### 에러 로깅 개선

```bash
# 에러 추적 개선
"에러가 발생했을 때 디버깅하기 어려워.
다음을 개선해줘:
1. 에러 메시지에 context 정보 추가 (user_id, request_id 등)
2. 구조화된 로깅 (winston 또는 pino 사용)
3. 중요한 에러는 Sentry에 자동 전송"
```

> **💡 팁:** "에러를 수정해줘"보다 "이 에러가 왜 발생하는지 먼저 설명해줘"라고 물어보는 것이 더 좋습니다. 원인을 이해하면 더 나은 해결책을 찾을 수 있고, 같은 에러가 재발하는 것을 막을 수 있습니다.

## 핵심 요약

1. **Bash 도구**는 실제 터미널 명령을 실행하며, 중요한 명령은 사용자 승인을 요청합니다
2. **TDD 워크플로우**를 Claude Code와 함께 수행하면 Red→Green→Refactor 사이클이 빨라집니다
3. **npm, pytest, gradle** 등 주요 빌드 도구와 자연스럽게 연동됩니다
4. 에러 디버깅 시 **완전한 에러 메시지 + 컨텍스트 + 재현 방법**을 함께 제공합니다
5. CI/CD 파이프라인 실패도 Claude Code가 로그를 분석하여 해결해줍니다
