## 15.1 GitHub Actions에서 Claude Code 실행하기

### 기본 워크플로우 설정

```yaml
# .github/workflows/claude-review.yml
name: Claude Code Review

on:
  pull_request:
    types: [opened, synchronize]
    branches: [main, develop]

jobs:
  code-review:
    runs-on: ubuntu-latest
    permissions:
      pull-requests: write
      contents: read

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 0  # 전체 히스토리 필요

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: "20"

      - name: Install Claude Code
        run: npm install -g @anthropic-ai/claude-code

      - name: Run Claude Code Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          # 변경된 파일 목록 가져오기
          CHANGED_FILES=$(git diff --name-only origin/main HEAD)

          # Claude Code로 리뷰 실행
          REVIEW=$(echo "$CHANGED_FILES" | claude -p "
          다음 파일들이 변경되었습니다:
          $CHANGED_FILES

          변경사항을 분석하고 다음을 포함한 코드 리뷰를 작성해줘:
          1. 버그 가능성
          2. 보안 이슈
          3. 성능 문제
          4. 코딩 컨벤션 위반
          5. 테스트 커버리지
          마크다운 형식으로 작성해줘.
          " --output-format text)

          # GitHub PR 코멘트로 게시
          gh pr comment ${{ github.event.number }} --body "$REVIEW"
```

### Secrets 설정

```
GitHub 저장소 → Settings → Secrets and variables → Actions

필요한 secrets:
- ANTHROPIC_API_KEY: Anthropic API 키
```

## 15.2 자동 PR 리뷰: 코딩 스타일, 보안, 성능 체크

### 고급 PR 리뷰 워크플로우

```yaml
# .github/workflows/advanced-review.yml
name: Advanced Code Review

on:
  pull_request:
    types: [opened, synchronize]

jobs:
  security-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - name: Security Review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          DIFF=$(git diff origin/main HEAD)

          SECURITY_REPORT=$(echo "$DIFF" | claude -p "
          이 코드 변경사항의 보안 리뷰를 수행해줘.

          확인 사항:
          - SQL 인젝션 가능성
          - XSS 취약점
          - 민감한 데이터 노출 (API 키, 비밀번호)
          - 인증/인가 우회 가능성
          - 입력 검증 누락

          Critical/High/Medium/Low로 분류해서
          마크다운으로 작성해줘.
          문제 없으면 '✅ 보안 검사 통과'라고 출력해줘.
          ")

          # Critical 이슈 있으면 PR 차단
          if echo "$SECURITY_REPORT" | grep -q "Critical"; then
            echo "::error::보안 Critical 이슈 발견"
            exit 1
          fi

          gh pr comment ${{ github.event.number }} \
            --body "## 🔒 보안 리뷰\n$SECURITY_REPORT"
```

### PR 리뷰 프롬프트 템플릿

```bash
# 상황별 리뷰 프롬프트

# 1. 신규 기능
"이것은 [기능명] 기능을 추가하는 PR입니다.
 비즈니스 요구사항: [요구사항]
 다음을 중점적으로 리뷰해줘:
 - 기능이 요구사항을 올바르게 구현했는가
 - 엣지 케이스 처리
 - API 설계의 일관성"

# 2. 버그 수정
"이것은 [버그 설명] 버그를 수정하는 PR입니다.
 원인: [버그 원인]
 다음을 확인해줘:
 - 수정이 실제로 버그를 해결하는가
 - 수정이 다른 기능을 깨뜨리지 않는가
 - 회귀 테스트가 추가되었는가"

# 3. 리팩토링
"이것은 리팩토링 PR입니다.
 기능 변경 없이 코드 품질만 개선해야 합니다.
 다음을 확인해줘:
 - 동작이 변경된 부분이 있는가
 - 테스트가 모두 통과하는가
 - 리팩토링 목표가 달성되었는가"
```

## 15.3 코드 문서화 자동화: JSDoc, docstring, README 생성

### JSDoc 자동 생성

```yaml
# .github/workflows/auto-docs.yml
name: Auto Documentation

on:
  push:
    branches: [main]
    paths:
      - "src/**/*.ts"
      - "src/**/*.js"

jobs:
  generate-docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Generate JSDoc
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          # 문서 없는 공개 함수 찾기
          FILES_WITHOUT_DOCS=$(grep -rl "export function\|export async function\|export class" src/ | head -10)

          for FILE in $FILES_WITHOUT_DOCS; do
            claude -p "
            $FILE 파일을 읽고 다음을 수행해줘:
            1. JSDoc 주석이 없는 공개 함수/클래스/메서드를 찾아줘
            2. 각각에 적절한 JSDoc 주석을 추가해줘
            3. @param, @returns, @throws, @example 태그를 포함해줘
            4. 파일을 직접 수정해줘
            "
          done

      - name: Commit docs
        run: |
          git config user.name "Claude Code Bot"
          git config user.email "claude-bot@company.com"
          git add -A
          git diff --staged --quiet || git commit -m "docs: JSDoc 자동 생성"
          git push
```

## 15.4 신규 팀원 온보딩 가이드 자동 생성

### 온보딩 문서 자동 생성

```bash
"이 프로젝트에 새로 합류한 개발자를 위한 온보딩 가이드를 만들어줘.

 포함 내용:
 1. 개발 환경 설정 (상세 단계별)
 2. 프로젝트 아키텍처 설명
 3. 주요 파일/폴더 설명
 4. 개발 워크플로우 (브랜치 전략, PR 프로세스)
 5. 자주 사용하는 명령어
 6. 팀 규칙과 컨벤션
 7. 자주 발생하는 문제와 해결법

 ONBOARDING.md로 저장해줘.
 새 팀원이 첫날 이 파일만 보고 개발 환경을 세팅할 수 있어야 해."
```

### 자동화된 온보딩 검증

```yaml
# .github/workflows/onboarding-test.yml
name: Onboarding Guide Test

on:
  push:
    paths: ["ONBOARDING.md"]

jobs:
  test-onboarding:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Validate onboarding guide
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: |
          claude -p "
          ONBOARDING.md를 읽고 다음을 검증해줘:
          1. 모든 명령어가 실제로 존재하고 올바른가 (package.json 확인)
          2. 환경 변수 목록이 .env.example과 일치하는가
          3. 언급된 파일 경로가 실제로 존재하는가
          4. 설치 단계가 논리적인 순서인가

          문제가 있으면 구체적으로 알려줘."
```

> **💡 팁:** 온보딩 가이드는 최소 분기별로 검토하세요. "ONBOARDING.md가 현재 코드베이스와 일치하는지 검증하고, 오래된 내용을 업데이트해줘"라고 요청하면 자동으로 최신화됩니다.

## 핵심 요약

1. **GitHub Actions**에 Claude Code를 연동하면 PR마다 자동 리뷰를 받습니다
2. 보안 Critical 이슈는 **PR 자동 차단**으로 코드베이스를 보호합니다
3. **JSDoc과 README**를 코드 변경에 맞춰 자동으로 업데이트합니다
4. 신규 팀원 **온보딩 가이드**를 자동 생성하고 주기적으로 검증합니다
5. CI/CD 파이프라인에 Claude Code를 포함하면 품질 게이트가 됩니다
