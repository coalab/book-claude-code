## 3.1 claude 명령어로 세션 시작하기

Claude Code는 터미널에서 실행되는 대화형 도구입니다. 가장 기본적인 실행 방법부터 시작합니다.

### 기본 실행

```bash
# 프로젝트 디렉토리로 이동
cd ~/my-project

# Claude Code 시작
claude
```

Claude Code는 **현재 디렉토리**를 작업 공간으로 인식합니다. 따라서 항상 프로젝트 루트 디렉토리에서 실행하는 것이 좋습니다.

### 시작 화면 이해

```
╭─────────────────────────────────────────────────────────────╮
│ ✻ Claude Code (v1.x.x)                                      │
│                                                             │
│   Type your request in natural language                    │
│   /help for commands | /exit to quit                       │
│                                                             │
│ Working directory: /home/user/my-project                   │
│ Model: claude-opus-4-5                                     │
╰─────────────────────────────────────────────────────────────╯

>
```

각 요소의 의미:
- **Working directory**: Claude Code가 파일을 읽고 쓸 기본 경로
- **Model**: 현재 사용 중인 AI 모델
- **>**: 명령 입력 프롬프트

### 슬래시 명령어

Claude Code에는 특수 명령어들이 있습니다:

| 명령어 | 설명 |
|--------|------|
| `/help` | 사용 가능한 명령어 목록 |
| `/exit` 또는 `/quit` | 세션 종료 |
| `/clear` | 대화 기록 초기화 |
| `/compact` | 컨텍스트 압축 |
| `/model` | 모델 변경 |
| `/cost` | 현재 세션 비용 확인 |
| `/doctor` | 환경 진단 |

## 3.2 자연어로 코드 생성 요청하기 (간단한 Python 스크립트 예제)

이제 실제로 첫 번째 요청을 해봅니다.

### 첫 번째 요청: 간단한 Python 스크립트

```
> 현재 날씨를 가져와서 출력하는 간단한 Python 스크립트를 만들어줘.
  OpenWeatherMap API를 사용하고, 서울 날씨를 보여줘.
  결과는 weather.py 파일로 저장해줘.
```

Claude Code의 응답:

```
weather.py 파일을 생성하겠습니다.

[Write 도구 사용 중...]

weather.py 파일을 생성했습니다. 다음 내용이 포함되어 있습니다:
```

생성된 파일:
```python
# weather.py
import requests
import os

def get_weather(city: str = "Seoul") -> dict:
    """
    OpenWeatherMap API로 날씨 정보를 가져옵니다.

    Args:
        city: 도시 이름 (기본값: Seoul)

    Returns:
        날씨 정보 딕셔너리
    """
    api_key = os.environ.get("OPENWEATHER_API_KEY")
    if not api_key:
        raise ValueError("OPENWEATHER_API_KEY 환경변수가 설정되지 않았습니다")

    url = f"https://api.openweathermap.org/data/2.5/weather"
    params = {
        "q": city,
        "appid": api_key,
        "units": "metric",
        "lang": "kr"
    }

    response = requests.get(url, params=params)
    response.raise_for_status()
    return response.json()


def display_weather(weather_data: dict) -> None:
    """날씨 정보를 사람이 읽기 쉬운 형태로 출력합니다."""
    city = weather_data["name"]
    temp = weather_data["main"]["temp"]
    feels_like = weather_data["main"]["feels_like"]
    description = weather_data["weather"][0]["description"]
    humidity = weather_data["main"]["humidity"]
    wind_speed = weather_data["wind"]["speed"]

    print(f"🌍 {city} 현재 날씨")
    print(f"{'─' * 30}")
    print(f"🌡️  기온: {temp:.1f}°C (체감 {feels_like:.1f}°C)")
    print(f"☁️  날씨: {description}")
    print(f"💧 습도: {humidity}%")
    print(f"💨 풍속: {wind_speed} m/s")


if __name__ == "__main__":
    weather_data = get_weather("Seoul")
    display_weather(weather_data)
```

이어서 실행까지:

```
> 실행해줘. API 키는 환경변수에 이미 있어.
```

```
[Bash 도구 사용 중...]
$ python weather.py

🌍 Seoul 현재 날씨
──────────────────────────────
🌡️  기온: 8.3°C (체감 5.1°C)
☁️  날씨: 맑음
💧 습도: 45%
💨 풍속: 3.2 m/s

실행이 완료되었습니다.
```

이것이 Claude Code의 기본 워크플로우입니다: **요청 → 파일 생성 → 실행 → 결과 확인**.

### 요청 작성 팁

```
❌ 모호한 요청:
"파이썬 스크립트 만들어줘"

✅ 구체적인 요청:
"현재 디렉토리의 CSV 파일들을 읽어서
 각 파일의 행 수, 열 수, 파일 크기를 표로 정리하고
 summary.txt로 저장하는 Python 스크립트를 만들어줘"
```

## 3.3 REPL 모드 vs 일회성 실행 (-p 플래그) 차이 이해

Claude Code는 두 가지 실행 모드를 지원합니다.

### REPL 모드 (기본)

```bash
claude
```

대화형 인터페이스가 열리며 여러 번 주고받을 수 있습니다. 이전 대화 내용이 컨텍스트로 유지됩니다.

```
사용 시나리오:
- 복잡한 개발 작업
- 반복적인 수정과 피드백
- 코드베이스 탐색
- 디버깅 세션
```

### 일회성 실행 (-p 플래그)

```bash
# 단일 명령 실행 후 종료
claude -p "package.json에서 버전 번호를 알려줘"

# 스크립트에서 활용
VERSION=$(claude -p "package.json의 version 필드 값만 출력해줘")
echo "현재 버전: $VERSION"
```

```
사용 시나리오:
- 자동화 스크립트
- CI/CD 파이프라인
- 빠른 일회성 질문
- 배치 처리
```

### 파이프 입력

```bash
# 파일 내용을 파이프로 전달
cat error.log | claude -p "이 에러 로그를 분석하고 원인을 설명해줘"

# git diff를 PR 설명으로 변환
git diff main | claude -p "이 변경사항을 PR 설명으로 작성해줘 (한국어)"

# 코드 리뷰 자동화
git show HEAD | claude -p "이 커밋을 코드 리뷰해줘. 문제점과 개선사항을 알려줘"
```

### 출력 형식 제어

```bash
# JSON 형식으로 출력 (스크립트 파싱용)
claude -p "package.json을 분석해서 의존성 목록을 JSON으로 반환해줘" \
  --output-format json

# 마크다운 없이 순수 텍스트
claude -p "이 함수를 한 줄로 설명해줘" --output-format text
```

> **💡 팁:** `-p` 플래그는 자동화에 매우 유용합니다. GitHub Actions에서 코드 리뷰, 릴리즈 노트 생성, 번역 작업 등을 자동화할 때 활용하세요. 15장에서 상세히 다룹니다.

## 3.4 세션 종료와 대화 기록 관리

### 세션 종료

```bash
# 방법 1: 슬래시 명령어
/exit

# 방법 2: Ctrl+C (또는 Ctrl+D)

# 방법 3: 자연어
"종료해줘"
```

### 컨텍스트 초기화

세션 중 대화가 너무 길어지거나 새로운 주제로 전환할 때:

```bash
# 대화 기록 완전 초기화 (새 세션 시작 효과)
/clear

# 컨텍스트 압축 (내용 유지하면서 토큰 절약)
/compact
```

### 대화 기록 저장

중요한 세션 내용을 저장하려면:

```bash
# 세션 중에 요청
"지금까지 논의한 내용을 session-notes.md로 저장해줘"

# 또는 터미널 출력 저장
claude | tee session-log.txt
```

### 세션 재개

Claude Code는 기본적으로 세션 간 메모리를 유지하지 않습니다. 이전 세션의 컨텍스트가 필요하다면:

1. `CLAUDE.md` 파일에 프로젝트 정보 기록 (8장 참조)
2. 세션 시작 시 관련 파일을 다시 읽도록 요청
3. 이전에 저장한 노트를 참조하도록 안내

```bash
# 새 세션 시작 시
claude
> CLAUDE.md와 지난 번 작성한 session-notes.md를 읽고
  우리가 어디까지 진행했는지 파악해줘
```

## 핵심 요약

1. `claude` 명령으로 현재 디렉토리를 작업 공간으로 하는 대화형 세션을 시작합니다
2. 자연어로 구체적인 요청을 하면 파일 생성, 실행, 검증까지 자동으로 처리됩니다
3. **REPL 모드**는 복잡한 개발 작업에, **-p 플래그**는 자동화와 일회성 작업에 사용합니다
4. `/clear`와 `/compact`로 대화 컨텍스트를 관리합니다
5. 세션 내용은 파일로 저장하여 다음 세션에서 참조할 수 있습니다
