# 챕터 4: 파일 읽기와 코드 이해
> Claude Code가 내 코드베이스를 파악하는 방법

## 학습 목표
- Read 도구의 동작 원리를 이해하고 효과적으로 활용한다
- 대형 코드베이스를 전략적으로 탐색하는 방법을 익힌다
- 레거시 코드를 Claude Code와 함께 분석하는 패턴을 학습한다
- 컨텍스트 한계를 관리하며 효율적으로 작업하는 기술을 습득한다

---

## 4.1 파일 읽기 도구(Read) 동작 원리와 활용법

Claude Code가 코드를 이해하려면 먼저 코드를 읽어야 합니다. 이것은 당연한 말처럼 들리지만, AI 코딩 도구에서 "읽는다"는 행위가 어떻게 작동하는지 이해하는 것은 Claude Code를 효과적으로 사용하는 첫 번째 열쇠입니다.

### Read 도구의 내부 구조

Claude Code의 Read 도구는 파일의 내용을 토큰 스트림으로 변환하여 모델의 컨텍스트 윈도우에 주입합니다. 일반적인 파일 뷰어와 달리, Claude Code는 파일을 읽는 순간 그 내용을 **이해**하기 시작합니다.

```
사용자: "src/auth/middleware.js 파일을 읽고 취약점을 분석해줘"

내부 처리 과정:
┌─────────────────────────────────────────────────┐
│  1. Read 도구 호출                               │
│     → file_path: "src/auth/middleware.js"       │
│     → offset: 0 (처음부터)                      │
│     → limit: 2000 (기본값: 줄 수)               │
│                                                 │
│  2. 파일 내용 → 토큰 변환                        │
│     → 코드 1,000줄 ≈ 약 5,000-8,000 토큰        │
│                                                 │
│  3. 컨텍스트 윈도우에 주입                       │
│     → Claude가 내용 분석 시작                   │
└─────────────────────────────────────────────────┘
```

### 기본 사용 패턴

Claude Code에게 파일을 읽도록 요청하는 방법은 여러 가지입니다:

```bash
# 명시적 요청
"package.json을 읽어줘"
"src/index.ts 파일의 내용을 보여줘"

# 분석 요청 (암시적 읽기)
"src/utils/parser.js에서 버그를 찾아줘"
"config/database.yml 설정을 검토해줘"

# 범위 지정 읽기 (대용량 파일)
"app.py의 100번 줄부터 200번 줄까지 읽어줘"
```

두 번째와 세 번째 패턴이 특히 중요합니다. 분석을 요청하면 Claude Code는 자동으로 파일을 읽고 분석을 수행합니다. 사용자가 "읽어줘"라고 명시할 필요가 없습니다.

### 줄 번호와 오프셋 활용

대용량 파일을 다룰 때는 특정 범위만 읽도록 지정할 수 있습니다:

```bash
# 대용량 파일의 특정 섹션 읽기
"database.py의 200번 줄부터 300번 줄 사이에 있는
 쿼리 함수들을 분석해줘"
```

Claude Code는 Read 도구의 `offset`과 `limit` 파라미터를 활용하여 필요한 부분만 읽습니다. 이는 50,000줄짜리 파일 전체를 컨텍스트에 올리는 비효율을 방지합니다.

> **💡 팁:** 파일이 2,000줄을 넘는다면, Claude Code는 자동으로 중요한 부분을 분할하여 읽습니다. 하지만 명시적으로 "~번 줄부터"라고 지정하면 더 정확한 분석이 가능합니다.

### 지원 파일 형식

Read 도구는 텍스트 기반 파일이라면 거의 모든 형식을 지원합니다:

| 카테고리 | 지원 형식 |
|---------|---------|
| 프로그래밍 언어 | .py, .js, .ts, .java, .go, .rs, .cpp, .c, .rb, .php |
| 설정 파일 | .json, .yaml, .yml, .toml, .ini, .env |
| 마크업 | .html, .css, .scss, .xml, .md, .mdx |
| 쉘 스크립트 | .sh, .bash, .zsh, .fish |
| 데이터 | .csv, .sql, .graphql |

바이너리 파일(이미지, 실행 파일 등)은 직접 읽을 수 없지만, PDF는 텍스트 추출을 통해 분석이 가능합니다.

## 4.2 대형 코드베이스 탐색: 디렉토리 구조 파악 전략

실제 프로젝트는 수백, 수천 개의 파일로 구성됩니다. 이런 코드베이스를 효율적으로 탐색하는 전략이 필요합니다.

### 탑다운 탐색 전략

처음 접하는 코드베이스는 항상 큰 그림부터 파악합니다:

```
Step 1: 루트 디렉토리 구조 파악
────────────────────────────────
"이 프로젝트의 전체 디렉토리 구조를 보여줘.
 주요 폴더와 파일의 역할을 설명해줘."

Claude Code의 행동:
- ls 또는 find 명령으로 구조 파악
- package.json, requirements.txt 등 설정 파일 확인
- README.md 읽기
- 엔트리 포인트 파일 식별

Step 2: 핵심 모듈 파악
────────────────────────────────
"이 프로젝트에서 가장 중요한 파일 5개는 뭐야?"

Step 3: 특정 기능 추적
────────────────────────────────
"사용자 인증 로직이 어디에 있어?"
```

### 실전 예제: Node.js 프로젝트 탐색

다음은 실제 팀 프로젝트를 처음 맡았을 때의 탐색 시나리오입니다:

```
프롬프트 순서:

1. "이 프로젝트의 package.json을 읽고 어떤 프로젝트인지 설명해줘"

2. "src 폴더의 구조를 분석해서 아키텍처 패턴을 파악해줘"

3. "API 라우트가 어디에 정의되어 있어? 전체 목록을 알고 싶어"

4. "데이터베이스 연결 설정은 어디에 있어?"

5. "테스트 파일들의 커버리지는 어때? 테스트 없는 주요 기능이 있어?"
```

각 단계마다 Claude Code는 자동으로 관련 파일들을 읽고 종합적인 답변을 제공합니다.

### 코드베이스 맵 생성

새 프로젝트 온보딩 시 가장 유용한 기법은 "코드베이스 맵"을 만드는 것입니다:

```bash
"이 프로젝트를 처음 보는 개발자를 위해
 다음 내용을 포함한 코드베이스 지도를 만들어줘:
 1. 전체 아키텍처 다이어그램 (텍스트)
 2. 주요 모듈별 역할 설명
 3. 데이터 흐름도
 4. 외부 의존성 목록
 5. 개발 시작 전 알아야 할 사항들"
```

결과물은 `ARCHITECTURE.md`로 저장해두면 팀 전체가 활용할 수 있습니다.

> **💡 팁:** `CLAUDE.md` 파일에 프로젝트의 핵심 파일 목록을 명시해두면, 매 세션마다 탐색하는 시간을 절약할 수 있습니다. 8장에서 자세히 다룹니다.

## 4.3 레거시 코드 분석 요청하기 (실전 예제: Express.js 앱)

레거시 코드 분석은 Claude Code가 가장 빛을 발하는 영역 중 하나입니다. 문서가 없고, 작성자도 없고, 이해하기 어려운 코드를 분석할 때 강력한 파트너가 됩니다.

### 분석 요청 패턴

다음은 오래된 Express.js 앱을 분석하는 실전 예제입니다:

```javascript
// 분석 대상 코드 (레거시 app.js)
var express = require('express');
var app = express();
var mysql = require('mysql');
var session = require('express-session');

var db = mysql.createConnection({
  host: 'localhost',
  user: 'root',
  password: '1234',
  database: 'myapp'
});

app.use(session({secret: 'secret', resave: true, saveUninitialized: true}));

app.get('/user/:id', function(req, res) {
  var id = req.params.id;
  db.query('SELECT * FROM users WHERE id = ' + id, function(err, rows) {
    if (err) throw err;
    res.json(rows[0]);
  });
});

app.post('/login', function(req, res) {
  var user = req.body.username;
  var pass = req.body.password;
  db.query("SELECT * FROM users WHERE username='" + user + "' AND password='" + pass + "'",
    function(err, rows) {
      if (rows.length > 0) {
        req.session.user = rows[0];
        res.json({success: true});
      }
    });
});

app.listen(3000);
```

이 코드를 Claude Code에게 분석 요청하는 방법:

```
"app.js를 읽고 다음을 분석해줘:
1. 보안 취약점 목록 (심각도 포함)
2. 성능 문제
3. 코드 품질 이슈
4. 현대적인 Express.js 패턴으로 개선하면 좋은 부분들"
```

Claude Code의 분석 결과 예시:

```
## 보안 취약점 분석

### 🚨 위험 (Critical)
1. **SQL Injection** (2곳)
   - /user/:id 라우트: 파라미터 직접 삽입
   - /login 라우트: username, password 직접 삽입
   → 해결책: Prepared statements 사용

2. **비밀번호 평문 저장**
   - users 테이블에 비밀번호가 평문으로 저장됨
   → 해결책: bcrypt 해싱

3. **하드코딩된 DB 자격 증명**
   - 소스코드에 DB 비밀번호 노출
   → 해결책: 환경변수 사용

### ⚠️ 경고 (Warning)
4. **취약한 세션 설정**
   - 예측 가능한 시크릿, 부적절한 세션 옵션
...
```

### 설명 요청 패턴

코드의 특정 부분이 이해되지 않을 때:

```bash
# 함수 설명 요청
"calculateTax 함수가 어떻게 동작하는지
 단계별로 설명해줘. 특히 엣지 케이스 처리 부분을 집중적으로"

# 비즈니스 로직 추론
"이 코드가 구현하는 비즈니스 규칙이 뭔지 설명해줘.
 주석도 없고 문서도 없어서 파악이 어려워"

# 의도 파악
"이 함수가 왜 이렇게 복잡하게 작성되어 있는지 이해가 안 돼.
 더 간단한 방법이 있을 것 같은데 원래 의도가 뭔지 추론해봐"
```

> **💡 팁:** 분석하기 전에 먼저 "이 코드의 목적이 뭔지 추론해줘"라고 물어보세요. Claude Code가 컨텍스트를 파악한 후 더 정확한 분석을 제공합니다.

### 종속성 분석

```bash
# 의존성 체인 파악
"UserService 클래스가 의존하는 모든 모듈과 클래스를
 트리 구조로 보여줘"

# 사용 현황 파악
"deprecatedHelper 함수가 프로젝트 어디서 사용되고 있어?
 삭제해도 안전한지 확인하고 싶어"

# 순환 참조 감지
"이 프로젝트에 순환 의존성이 있는지 확인해줘"
```

## 4.4 컨텍스트 한계 관리: 필요한 파일만 선택적으로 읽히기

Claude Code의 강점 중 하나는 방대한 컨텍스트 윈도우입니다. 하지만 무한하지는 않습니다. 효율적인 컨텍스트 관리는 응답 품질과 비용 모두에 영향을 미칩니다.

### 컨텍스트 윈도우 이해

```
Claude의 컨텍스트 윈도우 구성:
┌─────────────────────────────────────────────┐
│                                             │
│  시스템 프롬프트 (CLAUDE.md 등)              │
│  ─────────────────────────────             │
│  대화 기록 (이전 메시지들)                   │
│  ─────────────────────────────             │
│  읽은 파일 내용들                           │
│  ─────────────────────────────             │
│  현재 요청                                  │
│                                             │
│  전체 한계: ~200,000 토큰                   │
│  (약 150,000 영문 단어 = 코드 약 15,000줄)  │
└─────────────────────────────────────────────┘
```

### 선택적 읽기 전략

**전략 1: 관련 파일만 요청**

```bash
# ❌ 비효율적
"전체 src 폴더를 읽고 버그를 찾아줘"

# ✅ 효율적
"인증 관련 버그를 찾으려고 해.
 auth 폴더와 middleware/auth.js만 읽어줘"
```

**전략 2: 인터페이스 먼저, 구현 나중**

```bash
# 큰 파일의 핵심만 먼저 파악
"database.js 파일에서 외부에서 사용하는
 함수 시그니처와 JSDoc만 읽어줘.
 구현 내용은 필요할 때 요청할게"
```

**전략 3: 점진적 탐색**

```bash
Step 1: "이 프로젝트에서 결제 처리 관련 파일이 뭐가 있어?"

Step 2: "payment-service.js의 전체 구조를 설명해줘
        (전체 코드 말고 클래스/함수 목록만)"

Step 3: "processPayment 함수만 자세히 읽어줘"
```

### /compact 명령 활용

세션이 길어져 컨텍스트가 가득 찰 때:

```bash
/compact
```

이 명령은 대화 내용을 요약하여 컨텍스트 공간을 확보합니다. 중요한 정보는 유지하면서 불필요한 중복 내용을 압축합니다.

> **💡 팁:** 새로운 기능 작업을 시작할 때는 새 세션을 여는 것이 좋습니다. 이전 세션의 컨텍스트가 오히려 현재 작업을 방해할 수 있습니다.

### .claudeignore 파일 설정

특정 파일이나 디렉토리를 Claude Code가 읽지 않도록 설정할 수 있습니다:

```
# .claudeignore
node_modules/
dist/
build/
*.log
.env
.env.local
coverage/
__pycache__/
*.pyc
.git/
```

이 파일을 프로젝트 루트에 두면 Claude Code가 자동으로 무시 목록을 적용합니다.

## 다음 챕터 미리보기

5장에서는 코드를 **읽는** 것에서 **수정하는** 것으로 넘어갑니다. Edit 도구와 Write 도구를 사용하여 실제 파일을 안전하게 수정하는 방법을 배웁니다. 특히 "문자열 매칭"이라는 Edit 도구의 핵심 원리를 이해하면, 왜 때로는 편집이 실패하는지, 그리고 어떻게 하면 항상 성공하는지 알게 됩니다.
