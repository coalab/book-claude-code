# 챕터 8: CLAUDE.md로 프로젝트 맥락 설정하기
> 팀과 AI가 공유하는 프로젝트 지침서 만들기

## 학습 목표
- CLAUDE.md의 역할과 자동 로딩 메커니즘을 이해한다
- 효과적인 CLAUDE.md를 작성하는 방법을 익힌다
- 계층적 CLAUDE.md 구조를 설계한다
- 팀 프로젝트에서 CLAUDE.md를 버전 관리한다

## 8.1 CLAUDE.md의 역할과 자동 로딩 메커니즘

매번 세션을 새로 시작할 때마다 프로젝트에 대한 맥락을 다시 설명하는 것은 번거롭습니다. CLAUDE.md는 이 문제를 해결합니다. 프로젝트의 "항상 기억해야 할 것들"을 영구적으로 기록하는 파일입니다.

### 자동 로딩 메커니즘

```
CLAUDE.md 로딩 순서:

1. ~/.claude/CLAUDE.md        ← 전역 설정 (모든 프로젝트 공통)
2. /project-root/CLAUDE.md   ← 프로젝트 설정
3. /project-root/src/CLAUDE.md ← 서브디렉토리 설정 (해당 폴더 작업 시)

→ 세 파일이 모두 있다면 순서대로 합쳐서 로딩됩니다.
```

Claude Code는 세션 시작 시 현재 디렉토리와 상위 디렉토리의 CLAUDE.md를 자동으로 읽습니다. 별도의 설정 없이도 작동합니다.

### CLAUDE.md가 없을 때 vs 있을 때

```
CLAUDE.md 없을 때:
─────────────────
> "UserService에 새 메서드 추가해줘"

Claude: "UserService가 어떤 클래스인지 알려주세요.
         어떤 패턴을 사용하는지, 의존성 주입 방식은
         어떻게 되는지 설명해 주시면..."

CLAUDE.md 있을 때:
─────────────────
> "UserService에 새 메서드 추가해줘"

Claude: "UserService.ts를 읽겠습니다.
         [파일 읽기...]
         CLAUDE.md에 따라 Repository 패턴과
         의존성 주입을 사용하겠습니다."
```

## 8.2 효과적인 CLAUDE.md 작성법

### 기본 구조

```markdown
# 프로젝트명

## 프로젝트 개요
[한 문단으로 이 프로젝트가 무엇인지 설명]

## 기술 스택
- 언어: TypeScript 5.x
- 런타임: Node.js 20
- 프레임워크: Express.js 4.x
- 데이터베이스: PostgreSQL 16 + Prisma ORM
- 테스트: Jest + Supertest
- 배포: Docker + AWS ECS

## 코딩 컨벤션
[팀이 따르는 코딩 규칙]

## 아키텍처
[코드 구조와 패턴 설명]

## 금지 사항
[절대 하면 안 되는 것들]

## 자주 사용하는 명령어
[개발 워크플로우 명령어]
```

### 실제 예제: Node.js SaaS 프로젝트

```markdown
# TaskFlow API

## 프로젝트 개요
TaskFlow는 팀 생산성 관리 SaaS 서비스의 백엔드 API입니다.
멀티테넌트 아키텍처로 구성되어 있으며, 각 테넌트는 독립된
데이터 공간을 가집니다.

## 기술 스택
- TypeScript 5.3 (strict 모드 필수)
- Node.js 20 LTS
- Express.js 4.18
- PostgreSQL 16 + Prisma 5.x
- Redis 7 (캐싱, 세션)
- Jest 29 + Supertest (테스트)
- Docker + AWS ECS (배포)

## 디렉토리 구조
```
src/
├── controllers/    # HTTP 요청 처리
├── services/       # 비즈니스 로직
├── repositories/   # 데이터 접근 계층
├── middleware/     # Express 미들웨어
├── types/          # TypeScript 타입 정의
├── utils/          # 유틸리티 함수
└── config/         # 환경 설정
```

## 코딩 규칙
1. **타입**: any 타입 절대 금지. unknown 사용 후 타입 가드 적용
2. **에러 처리**: 모든 async 함수는 try-catch 또는 Result 타입 사용
3. **네이밍**: 인터페이스는 I 접두사 없이 (User, not IUser)
4. **임포트**: 절대 경로 사용 (@/services/user 형식)
5. **테스트**: 새 기능은 반드시 단위 테스트 포함

## 아키텍처 패턴
- Repository 패턴: 데이터 접근은 반드시 Repository 계층 통해서만
- Service 계층: 비즈니스 로직은 Controller에 넣지 말 것
- 의존성 주입: tsyringe 사용, @injectable() 데코레이터 필수

## 멀티테넌트 주의사항
- 모든 DB 쿼리에 tenantId 필터 필수
- RLS (Row Level Security) 정책 준수
- 테넌트 간 데이터 절대 혼용 금지

## 금지 사항
- console.log 사용 금지 (logger.info/error 사용)
- 직접 SQL 쿼리 금지 (Prisma 통해서만)
- .env 파일 git에 커밋 금지
- 테스트 없는 PR 머지 금지

## 개발 명령어
```bash
npm run dev          # 개발 서버 (hot reload)
npm test             # 전체 테스트
npm run test:watch   # 테스트 감시 모드
npm run db:migrate   # DB 마이그레이션
npm run db:seed      # 테스트 데이터 삽입
npm run lint         # ESLint 검사
```

## 환경 변수
필요한 환경 변수는 .env.example을 참고하세요.
절대 실제 값을 CLAUDE.md에 작성하지 마세요.
```

> **💡 팁:** CLAUDE.md는 새 팀원 온보딩 문서 겸 AI 지침서입니다. "새로 합류한 시니어 개발자에게 프로젝트를 설명한다"는 마음으로 작성하세요.

## 8.3 계층적 CLAUDE.md 구성

대형 프로젝트는 루트 CLAUDE.md 하나로는 부족할 수 있습니다. 서브디렉토리별로 특화된 지침을 제공할 수 있습니다.

### 모노레포 예시

```
my-monorepo/
├── CLAUDE.md              ← 전체 공통 (모노레포 구조, 공통 규칙)
├── packages/
│   ├── api/
│   │   └── CLAUDE.md      ← API 서버 특화 (Express, DB 패턴)
│   ├── web/
│   │   └── CLAUDE.md      ← 프론트엔드 특화 (React, 스타일 가이드)
│   └── shared/
│       └── CLAUDE.md      ← 공유 패키지 (타입, 유틸리티)
└── infrastructure/
    └── CLAUDE.md          ← 인프라 특화 (Terraform, AWS)
```

루트 CLAUDE.md:
```markdown
# MyApp 모노레포

## 전체 구조
- packages/api: Express.js REST API 서버
- packages/web: Next.js 웹 애플리케이션
- packages/shared: 공유 타입/유틸리티
- infrastructure: Terraform + AWS 인프라

## 공통 규칙
- 모든 패키지는 TypeScript strict 모드
- Conventional Commits 규칙 준수
- PR 전 `npm run lint && npm test` 통과 필수

## 패키지 간 의존성
shared ← api, web (shared가 다른 패키지에 의존하면 안 됨)
```

## 8.4 팀 프로젝트에서 CLAUDE.md 버전 관리 전략

### git으로 CLAUDE.md 관리

CLAUDE.md는 반드시 git으로 관리해야 합니다:

```bash
# .gitignore에서 제외 (CLAUDE.md는 커밋 대상)
# .gitignore 파일에 CLAUDE.md가 없는지 확인

# CLAUDE.md를 커밋
git add CLAUDE.md
git commit -m "docs: CLAUDE.md에 신규 API 패턴 추가"
```

### 팀 워크플로우

```
CLAUDE.md 업데이트 프로세스:

1. 새로운 패턴/규칙이 결정되면
   → CLAUDE.md PR 생성

2. 팀 리뷰 및 승인
   → 다른 개발자들이 AI가 어떤 지침을 받는지 확인

3. 머지 후 모든 팀원에게 공유
   → "CLAUDE.md 업데이트됨, 확인 필요"

4. 정기 리뷰 (월 1회)
   → 현재 실제 코드와 CLAUDE.md가 일치하는지 점검
```

> **💡 팁:** CLAUDE.md를 문서화 도구로도 활용하세요. "팀의 코딩 결정 사항들을 CLAUDE.md에 추가해줘"라고 요청하면, Claude Code가 대화 내용을 정리해서 CLAUDE.md를 업데이트합니다.

## 핵심 요약

1. **CLAUDE.md**는 세션 시작 시 자동으로 로딩되는 프로젝트 지침서입니다
2. 기술 스택, 코딩 규칙, 아키텍처 패턴, 금지 사항을 포함합니다
3. **계층적 구조**로 루트부터 서브디렉토리까지 특화된 지침을 제공합니다
4. 반드시 **git으로 버전 관리**하여 팀 전체가 공유합니다
5. "새 팀원에게 설명하는 문서"와 동일한 수준으로 작성합니다
