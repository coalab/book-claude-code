## 5.1 Edit 도구의 작동 방식: 정확한 문자열 매칭 원리

Claude Code의 Edit 도구는 단순한 텍스트 치환이 아닙니다. **정확한 문자열 매칭**을 기반으로 작동하며, 이 특성이 도구의 안전성과 예측 가능성을 보장합니다.

### 핵심 원리

```
Edit 도구의 작동 방식:

old_string: [변경할 기존 텍스트 - 파일에서 정확히 일치해야 함]
    ↓
파일에서 exact match 탐색
    ↓
new_string: [대체할 새 텍스트]

⚠️ 중요: old_string이 파일에 정확히 존재하지 않으면 편집 실패!
```

이 방식의 장점:
1. **의도하지 않은 변경 방지**: 비슷하지만 다른 코드를 실수로 수정하지 않음
2. **예측 가능성**: 편집 결과가 항상 명확함
3. **안전성**: 중복 패턴이 있으면 명시적으로 더 많은 컨텍스트 요구

### 편집 성공/실패 패턴

**성공 케이스:**
```python
# 원본 파일 내용
def calculate_discount(price, discount_rate):
    return price * discount_rate

# 편집 요청
old: "return price * discount_rate"
new: "return price * (1 - discount_rate)"

# 결과: 성공 ✓
```

**실패 케이스:**
```python
# 원본 파일 내용
def calculate_tax(amount):
    return amount * 0.1  # 10% tax

# 편집 요청 (공백 불일치)
old: "return amount * 0.1 # 10% tax"  ← 탭 vs 스페이스 불일치
new: "return amount * TAX_RATE"

# 결과: 실패 ✗ (정확히 일치하지 않음)
```

### Edit vs Replace_all

```bash
# 단일 수정 (기본값)
"LoginButton 컴포넌트의 className을 'btn-primary'에서
 'btn-login'으로 변경해줘"
→ Edit 도구, replace_all=false

# 전체 치환
"프로젝트 전체에서 'apiUrl'을 'API_URL'로 이름을 바꿔줘"
→ Edit 도구, replace_all=true (여러 파일에 걸쳐 적용)
```

> **💡 팁:** 편집이 실패할 경우, 더 많은 컨텍스트(주변 코드)를 포함하여 다시 요청하세요. "5번 줄의 return 문을 수정해줘"처럼 위치를 명시하면 도움이 됩니다.

## 5.2 Write 도구로 새 파일 생성하기 (모듈, 컴포넌트, 설정 파일)

Write 도구는 새 파일을 생성하거나 기존 파일을 완전히 덮어씁니다. Edit 도구가 "수술"이라면 Write 도구는 "새로 만들기"입니다.

### 새 모듈 생성

```bash
# 유틸리티 함수 모듈 생성
"src/utils/dateFormatter.ts 파일을 새로 만들어줘.
 다음 기능을 포함해야 해:
 - 날짜를 'YYYY-MM-DD' 형식으로 변환
 - 상대적 시간 표시 ('3일 전', '방금 전' 등)
 - 한국 공휴일 처리
 TypeScript로 작성하고 Jest 테스트도 같이 만들어줘"
```

결과:
```typescript
// src/utils/dateFormatter.ts
export const formatDate = (date: Date): string => {
  const year = date.getFullYear();
  const month = String(date.getMonth() + 1).padStart(2, '0');
  const day = String(date.getDate()).padStart(2, '0');
  return `${year}-${month}-${day}`;
};

export const getRelativeTime = (date: Date): string => {
  const now = new Date();
  const diffMs = now.getTime() - date.getTime();
  const diffSecs = Math.floor(diffMs / 1000);
  const diffMins = Math.floor(diffSecs / 60);
  const diffHours = Math.floor(diffMins / 60);
  const diffDays = Math.floor(diffHours / 24);

  if (diffSecs < 60) return '방금 전';
  if (diffMins < 60) return `${diffMins}분 전`;
  if (diffHours < 24) return `${diffHours}시간 전`;
  if (diffDays < 30) return `${diffDays}일 전`;
  return formatDate(date);
};
```

### 파일 덮어쓰기 주의사항

```
Write 도구 사용 전 확인 사항:

✓ 기존 파일의 중요한 내용이 없는가?
✓ git에 커밋되지 않은 변경사항이 없는가?
✓ 팀원이 동시에 수정 중이지 않은가?

Claude Code는 기존 파일을 Write로 덮어쓰기 전에
항상 현재 내용을 읽고 검토합니다.
```

> **💡 팁:** 기존 파일을 대규모로 수정할 때는 Write 대신 Edit을 사용하는 것이 안전합니다. Write는 파일 전체를 교체하므로 의도치 않은 내용 손실 위험이 있습니다.

## 5.3 리팩토링 요청 패턴: 함수 추출, 네이밍 개선, 중복 제거

리팩토링은 Claude Code가 특히 잘 수행하는 작업입니다. 코드를 이해하고, 패턴을 인식하고, 안전하게 변환하는 과정을 자동화합니다.

### 함수 추출 리팩토링

```javascript
// 리팩토링 전 (긴 함수)
async function processOrder(orderId) {
  const order = await db.query(`SELECT * FROM orders WHERE id = ${orderId}`);

  // 재고 확인
  for (const item of order.items) {
    const stock = await db.query(`SELECT stock FROM products WHERE id = ${item.productId}`);
    if (stock < item.quantity) {
      throw new Error(`재고 부족: ${item.productId}`);
    }
  }

  // 결제 처리
  const payment = await paymentAPI.charge({
    amount: order.total,
    currency: 'KRW',
    customerId: order.customerId
  });

  // 재고 차감
  for (const item of order.items) {
    await db.query(`UPDATE products SET stock = stock - ${item.quantity} WHERE id = ${item.productId}`);
  }

  // 이메일 발송
  const customer = await db.query(`SELECT * FROM users WHERE id = ${order.customerId}`);
  await emailService.send({
    to: customer.email,
    subject: '주문이 완료되었습니다',
    body: `주문번호 ${orderId} 처리가 완료되었습니다.`
  });

  return payment;
}
```

리팩토링 요청:
```bash
"processOrder 함수를 읽고 다음 기준으로 리팩토링해줘:
1. 각 기능(재고확인, 결제, 재고차감, 이메일)을 별도 함수로 추출
2. SQL 인젝션 취약점 수정 (파라미터화된 쿼리 사용)
3. 에러 처리 개선
4. 트랜잭션 처리 추가"
```

### 네이밍 개선

```bash
# 전체 파일의 변수명 개선
"auth.js 파일을 읽고 다음 네이밍 컨벤션을 적용해줘:
- 불리언 변수는 is/has/can으로 시작 (예: isLoggedIn, hasPermission)
- 이벤트 핸들러는 handle로 시작 (예: handleClick, handleSubmit)
- 비동기 함수는 fetch/load/save로 시작
- 축약어 사용 금지 (usr → user, pwd → password)
변경 전/후 목록을 보여줘"
```

### 중복 제거

```bash
"components 폴더를 분석해서 중복된 코드 패턴을 찾아줘.
특히:
- 비슷한 폼 유효성 검사 로직
- 중복된 API 호출 패턴
- 동일한 스타일 계산

중복을 제거하기 위한 공유 훅이나 유틸리티 함수를 제안해줘"
```

### 리팩토링 안전성 검증

```bash

확인할 수 있는 테스트를 작성해줘.
특히 엣지 케이스를 집중적으로 다뤄줘"
```

## 5.4 대규모 편집 시 안전성 확보: 변경사항 검토와 되돌리기

여러 파일에 걸친 대규모 변경은 신중하게 접근해야 합니다.

### 변경 전 안전망 구성

```bash
# 1. git 상태 확인
"현재 git 상태를 보여줘. 커밋되지 않은 변경사항이 있어?"

# 2. 작업 브랜치 생성
"refactor/auth-module 브랜치를 만들고 체크아웃해줘"

# 3. 변경 계획 먼저 수립
"auth 모듈을 리팩토링하려는데, 시작하기 전에
 변경될 파일 목록과 각 파일에서 어떤 변경이 일어날지 계획을 먼저 보여줘.
 실제 변경은 내가 확인 후 진행할게"
```

### 단계적 변경 패턴

```
대규모 리팩토링의 올바른 순서:

Step 1: 계획 수립 (파일 목록, 변경 내용 요약)
Step 2: 변경 범위가 좁은 것부터 시작
Step 3: 각 단계마다 테스트 실행
Step 4: git commit으로 체크포인트 생성
Step 5: 다음 단계로 진행

❌ 잘못된 방법: 모든 파일을 한 번에 변경
✓ 올바른 방법: 모듈 단위로 나눠서 점진적 변경
```

### 변경사항 검토

```bash
# 변경 후 리뷰 요청
"방금 한 변경사항을 git diff로 보여주고,
 의도치 않은 변경이 있는지 검토해줘"

# 영향 범위 분석
"이 변경이 다른 파일에 영향을 미칠 수 있는지 확인해줘.
특히 import 하는 파일들이 여전히 정상 동작하는지"
```

### 되돌리기 전략

```bash
# git을 활용한 안전한 되돌리기
"방금 한 변경이 마음에 안 들어. git stash로 임시 저장하고
 원래 상태로 돌아가줘"

# 특정 파일만 되돌리기
"auth.js만 최근 커밋 상태로 되돌려줘"
```

> **💡 팁:** 대규모 리팩토링을 시작하기 전에 항상 "이 변경으로 인해 깨질 수 있는 것들은 뭐가 있어?"라고 먼저 물어보세요. Claude Code가 위험 요소를 미리 파악해줍니다.

## 핵심 요약

1. **Edit 도구**는 정확한 문자열 매칭으로 안전하게 파일을 수정합니다
2. **Write 도구**는 새 파일 생성이나 전체 덮어쓰기에 사용합니다
3. 리팩토링은 **함수 추출 → 네이밍 → 중복 제거** 순으로 접근합니다
4. 대규모 변경은 **브랜치 생성 → 계획 수립 → 단계적 실행 → 검토** 패턴을 따릅니다
5. git을 안전망으로 활용하여 언제든 되돌릴 수 있게 합니다
